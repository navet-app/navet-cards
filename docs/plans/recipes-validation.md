# Local reusable configurations

T01 provides a local, HA-owned `definitions` map, ordered `use` names and per-card scalar `variables`. Each definition has `config`, optional ordered `extends`, and variable defaults. Later definitions override earlier definitions; local card fields override all selected definitions. Local definition names shadow inherited composition scope as complete definitions. No dashboard-global registry is created.

`resolveRecipes` is a pure materializer. Callers retain raw saved references, validate the resolved card and separately materialize runtime state. It removes `use` and `variables` from runtime output, retaining a cloned definitions scope for child hosts. Nested card objects are opaque during interpolation; each Navet child resolves its own context explicitly. Third-party child configs receive no injected definitions or interpolation.

Objects merge recursively. Arrays replace, except the root Navet `chips`, `sub_controls`, and `sub_control_groups` arrays: when every member has a unique nonempty string `id`, matching members merge and new members append in order. An explicit empty array clears inherited members. Arbitrary nested arrays and third-party card lists always replace; no guessed entity/index matching occurs. This slice does not add deletion markers for individual inherited members.

Variables accept strings, finite numbers, booleans and null. An exact `${name}` placeholder preserves its scalar type. Embedded placeholders become text. Variable values are never evaluated or recursively interpolated. Plain configs without selected definitions or declared variables retain literal placeholders. No JavaScript, Jinja, network access or global state is involved.

Definitions and references diagnose missing names, cycles and missing selected variables. Safety guards reject accessor/non-JSON objects, dangerous prototype keys, more than 32 inheritance levels, nesting beyond 48 levels, more than 50,000 source/output nodes or excessive merge work. These are configuration-safety guards; bundle ceilings remain removed.

The visual editor creates/removes definitions, edits complete configurations through the existing child visual editor, orders `extends` and `use`, edits typed variables and their names, imports/exports definitions JSON and materializes the current card. Partial configurations and placeholder expressions can use the existing complete JSON replacement. Invalid drafts remain local; common parent field edits preserve those drafts. There is no YAML requirement for ordinary creation and reuse.
